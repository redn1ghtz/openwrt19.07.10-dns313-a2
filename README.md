## 1. Назначение

`build_dns313_a2_openwrt.py` подготавливает образ OpenWrt 19.07.10, редактируя официальный образ [OpenWrt D-Link DNS-313 ревизии B1](https://openwrt.org/toh/d-link/dns-313) для **D-Link DNS-313 аппаратной ревизии A2** (Gemini SL3512, 32 МиБ RAM (возможно, это работает и для A1, но это не подтверждено)). Исходником служит **уже скачанный** заводской образ `openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin` (допускается `.gz`). Скрипт **не скачивает** прошивку и **никогда не записывает физические диски**: читает исходный файл и создаёт новый файл образа.

Почему именно версия 19.07.10? Она выбрана исключительно ради оптимизации на слабом процессоре и всего 32МиБ оперативной памяти. На странице [OpenWrt D-Link DNS-313 ревизии B1](https://openwrt.org/toh/d-link/dns-313) указана последняя поддерживаемая версия 25.12.5, но именно в ревизии A2 урезан объем памяти, поэтому работа на 25.12.5 крайне нестабильна и свободной памяти почти не остается, хотя она запускается после некоторых изменений. В дальнейшем возможно я попробую её оптимизировать.

**Внимание:** последующая ручная запись образа на HDD стирает его разметку и данные в перезаписываемой области. **Никогда не копируйте команды записи без проверки реального имени диска.** В самом NAS тот же HDD обычно называется `/dev/sda`.

<a id="chapter-1"></a>
## 2. Что делает скрипт

| Раздел в NAS | Назначение | Начальный сектор | Размер в образе | Файловая система |
|---|---|---:|---:|---|
| `/dev/sda1` | Данные | Создаётся вручную | Отсутствует в образе | ext4 создаётся вручную через `mkfs.ext4` |
| `/dev/sda2` | Swap | 559104 | 128 МиБ | Linux swap, создаётся `mkswap` при сборке |
| `/dev/sda3` | Загрузка | 63 | ~16,1 МиБ | ext2, загрузочные файлы |
| `/dev/sda4` | Корневая система OpenWrt | 33075 | ~256 МиБ | ext4 |

Нумерация разделов **не совпадает с их физическим порядком** на диске: сначала загрузочный раздел 3, затем корневой 4, swap 2 и раздел данных 1.

Образ содержит исправления заголовков D-Link/CRC, DTB для 32 МиБ RAM, настройки I²C GPIO для восстановления работы управления системным вентилятором и аргументы ядра `root=/dev/sda4`. В `/etc/config/network` записывается постоянный MAC для интерфейса LAN. Устанавливается ранний запуск swap `/etc/rc.d/S00dns313-swap`, который включает `/dev/sda2` при загрузке.

Скрипт **спрашивает**, отключать ли необязательные службы и автозагрузку ненужных модулей. По умолчанию **да**: профиль отключения необязательных служб и модулей применяется при нажатии Enter. При ответе «да» удаляются только записи автозапуска; пакеты и сами модули с файловой системы не удаляются.

**Автомонтирование `/dev/sda1` скрипт не настраивает.** Он не создаёт `/etc/config/fstab` с записью для диска данных. При этом он не гарантирует удаления конфигурации, уже присутствующей в исходном образе. `/dev/sda4` — системный корень `/`, его монтирование обязательно.

<a id="chapter-2"></a>
## 3. Подготовка Debian-компьютера

Протестировано на `debian-12.15.0-amd64`

Установите зависимости и склонируйте репозиторий:

```bash
sudo apt update
sudo apt install python3 e2fsprogs device-tree-compiler util-linux fdisk
git clone https://github.com/redn1ghtz/openwrt19.07.10-dns313-a2.git
cd openwrt19.07.10-dns313-a2
```

Для сборки требуются `python3`, `debugfs`, `e2fsck`, `fdtget`, `fdtput`, `mkswap`. Для последующих операций с HDD нужны `lsblk`, `fdisk`, `mkfs.ext4`, `resize2fs` (последний для этой схемы обычно не нужен).

Скачайте образ D-Link DNS-313 (на сайте есть **[официальная инструкция по установке](https://openwrt.org/toh/d-link/dns-313)**, но она предназначена **для ревизии B1**, это не указано) с официального репозитория [OpenWrt](https://downloads.openwrt.org/releases/19.07.10/targets/gemini/generic/openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin.gz) (за основу берется образ D-Link DNS-313 ревизии B1). Если репозиторий недоступен, возьмите образ в папке проекта.

```bash
curl https://downloads.openwrt.org/releases/19.07.10/targets/gemini/generic/openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin.gz
```

Положите в папку проекта и распакуйте образ OpenWrt 19.07.10:

```bash
gunzip openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin.gz
```

Эти файлы должны быть в одной папке:

```text
build_dns313_a2_openwrt.py
openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin
```

<a id="chapter-3"></a>
## 4. Сборка образа

```bash
python3 build_dns313_a2_openwrt.py \
  --input openwrt-19.07.10-gemini-dlink_dns-313-ext4-factory.bin \
  --output dns313-a2-ready.img
```

Имя выходного файла должно быть **новым**: скрипт отказывается перезаписывать существующий файл.

При запросе:

```text
DNS-313 label MAC ID (press Enter to generate a persistent random MAC):
```

Введите MAC с наклейки в формате `00:00:00:00:00:00`, или нажмите Enter. При Enter создаётся случайный локальный unicast MAC; он будет постоянным **для данного собранного образа**. Новая сборка с Enter может получить другой MAC.

После ввода MAC скрипт спрашивает:

```text
Disable optional services and unused modules? [Y/n]:
```

- **n / нет** — ничего не отключать. Сохранить исходные записи автозапуска служб и модулей.
- **Enter / y / да** (значение по умолчанию, рекомендуется) — применить профиль отключения ненужных служб и модулей **к создаваемому образу**.

При выборе **y** удаляются ссылки `/etc/rc.d/S??...` для `samba`, `samba4`, `smbd`, `nmbd`, `mdadm`, `dnsmasq`, `odhcpd`, `firewall`, если они присутствуют в исходном образе. **Осторожно:** отключение `dnsmasq`, `odhcpd` и `firewall` меняет сетевые функции NAS. Это допустимо только при заранее продуманной сетевой конфигурации; если эти функции нужны, явно выберите **n**.

Также отключаются записи загрузки модулей RAID (`28-md-linear`, `28-md-raid456`, `29-md-multipath`), NTFS (`30-fs-ntfs`), ReiserFS (`30-fs-reiserfs`), VFAT (`30-fs-vfat`), NFS/RPC (`31-fs-nfs-common-rpcsec`), а также соответствующие строки модулей Btrfs, RAID, NFS и CIFS, если они есть. Если удаляется файл `/etc/modules.d/`, его одноимённая ссылка в `/etc/modules-boot.d/` тоже удаляется, чтобы не возникало ошибки `kmodloader: failed to open`. Убираются битые ссылки Btrfs/ReiserFS.

Это именно **автозагрузка**, а не удаление пакетов через `opkg`. При желании можно включить автозагрузку.

После успешной сборки проверьте итоговое сообщение, путь выходного файла и SHA256. Если сборка завершилась ошибкой, **не записывайте** частичный или неподтверждённый образ на HDD.

<a id="chapter-4"></a>
## 5. Запись на HDD

Подключите предназначенный для NAS HDD к Debian. **Сначала определите диск по модели, серийному номеру и ёмкости:**

```bash
lsblk -o NAME,PATH,SIZE,MODEL,SERIAL,TYPE,MOUNTPOINTS
```

Вместо 'X' в поля '/dev/sdaX' подставьте букву Вашего HDD для NAS, полученную в предыдущем пункте. Убедитесь, что разделы целевого HDD не смонтированы и диск не используется.

```bash
sudo dd if=dns313-a2-ready.img of=/dev/sdX
sync
```

**`dd` уничтожает прежнее содержимое начала указанного диска.**

<a id="chapter-5"></a>
## 6. Первое включение

Безопасно отключите HDD от компьютера и установите в NAS, подключите сетевой кабель от роутера, затем включите.

Подождите пару минут для загрузки системы (также устройство может пару раз выключиться при первом запуске, включите его обратно кнопкой). Определите IP адрес NAS (можете использовать веб-интерфейс роутера) и перейдите в браузере по его адресу.

В веб-интерфейсе зайдите в раздел System -> General Settings, настройте правильное время и часовой пояс, примените натройки Save & Apply.

<a id="chapter-6"></a>
## 7. Создание раздела данных

В записанном образе **нет раздела 1**. Разделы 2 (swap), 3 (boot), 4 (root) уже существуют. Теперь создайте `/dev/sdb1` на оставшемся пространстве HDD. Ни один существующий раздел не удаляйте и не изменяйте.

Подключитесь к NAS по SSH.

```sh
fdisk /dev/sda
```
Нажмите n, p ENTER, ENTER, ENTER, ENTER, w чтобы создать /dev/sda1.
```sh
mkfs.ext4 /dev/sda1
```

Используйте инструмент *block*, чтобы настроить раздел /dev/sda1 для монтирования:

```sh
opkg update
opkg install block-mount
block detect | uci import fstab
uci set fstab.@mount[0].enabled='1'
uci commit fstab
```
Вы можете убедиться, что мы настроили /dev/sda1 для монтирования с помощью:
```sh
cat /etc/config/fstab
```
Обязательно перезагрузите NAS!

## 8. Установка и настройка остановки HDD при простое (hd-idle)

`hd-idle` останавливает вращение диска после периода без обращений. Это **не отключение питания** и не размонтирование `/dev/sda1`: раздел может оставаться смонтированным. При следующем обращении HDD автоматически раскрутится. Функция не связана с отображением диска в блоке Memory LuCI.

Подключитесь к OpenWrt по SSH:

```sh
opkg update
opkg install hd-idle
/etc/init.d/hd-idle enable
/etc/init.d/hd-idle restart
```

Для управления через LuCI, дополнительно:

```sh
opkg install luci-app-hd-idle
```

Перезагрузите NAS, зайдите в веб-интерфейс OpenWrt и перейдите в Services -> HDD Idle.

Установите галочку 'Enable'

'Disk' виберите 'sda'

'Idle time' установите время по истечению которого будет отключаться HDD

'Idle time unit' единица измерения времени

Примените изменения Save & Apply

## 9. Установка и настройка SMB-сервера ksmbd

`ksmbd` предоставляет доступ к папке HDD из Windows, Linux и других SMB-клиентов. На DNS-313 с 32 МиБ ОЗУ он предпочтительнее тяжёлого Samba-сервера.

```sh
opkg update
opkg install kmod-fs-ksmbd ksmbd-server ksmbd-utils
/etc/init.d/ksmbd enable
/etc/init.d/ksmbd restart
```

Для управления через LuCI :

```sh
opkg install luci-app-ksmbd
```
Перезагрузите NAS, зайдите в веб-интерфейс OpenWrt и подключитесь по SSH.
Создайте папку и назанчьте владельца:

```sh
mkdir -p /mnt/sda1/Public
chown nobody:nogroup /mnt/sda1/Public
chmod 0770 /mnt/sda1/Public
ls -ld /mnt/sda1/Public
```

В веб-интерфейсе перейдите к разделу Services -> Network Shares

Заполните поля:

**Interfaces -> lan**

**WORKGROUP -> WORKGROUP**

**Description -> любое описание**

**Allow legacy (insecure) -> выключено**

Shared Directories -> Add:

**Name -> Data**

**Path -> mnt/sda1/Public**

**Browseable -> включено**

**Read-only -> выключено**

**Force Root -> выключено**

**Allowed users -> оставьте пустым**

**Allow guests -> включено**

**Inherit owner -> выключено**

**Hide dot files -> включено**

**Create mask -> 0666**

**Directory mask -> 0777**

В Windows откройте в проводнике `\\IP_АДРЕС_NAS\Data`, подставив текущий IP устройства. Если Windows блокирует гостевой доступ, безопаснее настроить SMB-пользователя, а не ослаблять политику безопасности Windows.

**Безопасность:** гостевая запись без пароля допустима только в доверенной LAN. Не открывайте TCP 445 в интернет. Устаревшая версия `ksmbd` в OpenWrt 19.07 имеет известные риски безопасности.

<a id="chapter-9"></a>
## 10. Установка из локальной папки `packages`, если репозиторий недоступен

Если официальный репозиторий OpenWrt не отвечает или в нём отсутствуют нужные версии, используйте подготовленные `.ipk` из папки **`packages`** рядом с инструкцией.

Скопируйте папку `packages` с компьютера на NAS, например по SCP в `/tmp/packages` (подставьте реальный IP NAS):

```bash
scp -r packages root@192.168.1.1:/tmp/
```

**На DNS-313 A2 всего 32 МиБ RAM:** `/tmp` находится в оперативной памяти, поэтому полный комплект может не поместиться. Предпочтительнее сначала смонтировать `/dev/sda1` и скопировать пакеты в `/mnt/sda1/packages`, либо передавать и устанавливать их небольшими группами. При использовании HDD замените путь `/tmp/packages` ниже на `/mnt/sda1/packages`.

На NAS:

```sh
cd /tmp/packages
ls -1 *.ipk
opkg install ./*.ipk
```
